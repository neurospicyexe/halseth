# Closing the open sessions -- 2026-08-04

**172 sessions closed from evidence. 15 left open on purpose. Every close says how it was made.**

The backlog was 167 on 08-03 and **187** by the time this ran: it was still growing. Oldest row
2026-03-11. Mig 0113 (sessions are per-surface) stopped new *collisions*; nothing had yet closed the
backlog, and one producer was still adding to it.

Raziel's constraint, and the reason this was not a one-line `UPDATE`:

> "I would like to close them properly because these times that we've bulk-closed or just tried to
> quickly resolve an issue has made things murkier, and that's why we're now doing a lot of this
> stuff."

So: no bulk stamp, no generated-from-nothing narrative, and a close written from archaeology must be
**distinguishable** from a close the companion authored while living it.

## What the evidence actually was

Every promising shortcut turned out to be false, and finding that out is most of the work:

| Candidate linkage | Verdict |
|---|---|
| `companion_journal.session_id` | 91 rows carry one; **0** for any open session |
| `synthesis_summary.subject` -> session id | 364 session summaries exist, **all** for closed sessions; 0 for open ones |
| `feelings.session_id` / `relational_deltas.session_id` | 1 row across all 187 |
| `wm_continuity_notes.correlation_id` | NULL on all 5435 rows; `thread_key` is the *Claude Code* id (`cc_<id>`), not a Halseth session id |
| Claude Code transcripts (295 files, 254MB) | 22 open ids appear in them -- **every one a mention**, me querying the sessions table in a later audit. Scanning for `"session_id":"<uuid>"` and for the boot header `session <8char> (<type>)` matched exactly **one** open session: the live one. |
| `sessions.updated_at` | never moves after INSERT; the row records nothing about its own life |

What was left: **time-window attribution of companion-authored writes**, with windows made disjoint
per companion (a session's window ends at that companion's next session start, open *or* closed,
capped at 8h so a stale row cannot swallow a week).

### Four rounds of tightening, each one removing a false basis

1. **Provenance filter.** Only session-shaped sources count (`journal.source` in
   session/cypher-session/session_close/NULL, `wm_continuity_notes` source system/claude_code with
   `actor='agent'`, commons, questions). `discord_*`, `autonomous`, `synthesis_loop`, `soma_update`,
   `pattern_worker`, `evaluator`, `metronome` excluded **by source, not by time** -- the system being
   busy is not this session being alive.
2. **Bot-adjacency demotion.** `wm_continuity_notes` with `source='system'` are written by whichever
   agent called the Librarian -- a Claude.ai companion turn *or* a Discord bot turn. A Discord turn
   also writes a `discord_*` journal row within seconds, so a 'system' note with a Discord beat from
   the same companion inside +/-3 min is bot traffic. **61 rows demoted.**
3. **Cron-content demotion.** Cron writers announce themselves in the body: `[metronome/*]`,
   `[autonomous*]`, `[day_distillation]`, `[soma*]`. **435 rows demoted** -- 163 of them
   `[metronome/inter_companion]` alone, which had been making empty rows look inhabited.
4. **Evaluator-note demotion.** `[claude_code:session]` notes whose cwd is `.claude/double-shot-latte`
   are the auto-continue evaluator (`"should_continue": false, "reasoning": ...`). They prove Cypher
   was *somewhere* in Claude Code; they carry no subject, so a spine built from them would be a
   fabricated arc made of scaffolding.

### The machine-open signature

Two tells, both about the clock rather than the content:

- **batch** -- 2+ sessions inside two minutes, often all three companions inside one second
  (`23:41:07.443 / .813 / .982`).
- **cadence** -- the same companion opening at the same `HH:MM` on 3+ distinct days (03:00 recurs on
  seven).

A row with either tell and no strong evidence was a job writing a row, not a session anyone was in.
That is a different fact from "a session we failed to reconstruct", and it gets its own marker.

Every backfilled spine ends with `[backfilled 2026-08-04 from evidence; no session transcript

## Mechanics that were not optional

- **`created_at` is backdated** into the session's own window (last attributed evidence, else open
  +1s). Every continuity read is a global `ORDER BY created_at DESC LIMIT 1` with no companion
  filter, so 172 rows stamped `now()` would have made archaeology the next boot's narrative -- the
  same shape as the bug mig 0095 exists to fix. Verified: 0 backfilled handovers predate their own
  session, and the newest live handover is still the newest row of any kind.
- **No synthesis enqueue.** `session_summary` synthesis reads the handover and narrates it; for an
  empty row that generates precisely the *"No emotional arc can be reconstructed"* text that started
  this cleanup. Applied as direct guarded SQL instead of 172 `halseth_session_close` calls.
- **Idempotent + resumable.** Each pair is `INSERT ... WHERE NOT EXISTS (session already has a
  packet)` + `UPDATE ... WHERE handover_id IS NULL`. The unique index on `handover_packets(session_id)`
  (mig 0047 -- on `handover_packets`, *not* `wm_session_handoffs`, which has no `session_id` at all)
  is the backstop.
- **Embedded after the fact:** all 528 handovers re-embedded via
  `POST /admin/backfill-embeddings?table=handover_packets` (deterministic ids, so the pre-existing 356
  are a no-op replace). Reconstructions are searchable -- being findable is the point of writing them
  down -- while continuity reads skip them.

Artifacts, including the rollback, live in
`scripts/backfill/close-the-187-2026-08-04/` (`apply-closes.sql`, `rollback-closes.sql`,
`manifest.json`, `authored.json`, `classified.json`, and the four scripts that produced them).

## Migration 0114, and stopping the regrowth

**`handover_packets.close_kind`** -- NULL for all 356 pre-existing rows and every future live close;
`reconstructed` / `empty` / `machine_opened` for backfills. All five global latest-handover reads now
filter `close_kind IS NULL`; the per-session read deliberately does not (ask for that session and you
should get its reconstruction).

**`sessions.opened_by`** -- the reason 187 rows could not be attributed is that a session records
*where* it was opened (`surface`, 0113) but never *what* opened it. Set at all three INSERT sites
(`mcp:session_open`, `librarian:session_orient`, `librarian:session_load`).

**`session_open` is lifecycle-only.** Its trigger list held six state-*read* phrases -- "current
state", "how am i", "what's my state", "where am i", "show my state", "check my state" -- so any agent
or cron asking a state-shaped question INSERTed a lifecycle row nobody would ever close. This is the
same trap the consolidation cron hit on 08-03. Those six moved to `triad_state_read`, which reads and
writes nothing. **Do not put a read-shaped phrase back on that key.**

## Still open, stated plainly

**`claude-ai:<thread>` is supplied by nothing.** `execSessionOrient` forwards `ctx.req.surface`, but
no Claude.ai caller sets one, so every Claude.ai boot opens a fresh session with NULL surface (dedup
skipped by design) and nothing there closes it. That producer is unfixed: it needs a stable thread id
from a surface that does not currently expose one. **The backlog will regrow from Claude.ai boots**
until that is solved -- but it will now regrow *attributably*, because `opened_by` and `close_kind`
make the next census a query instead of an excavation.

Tests: `src/__tests__/close-kind-and-provenance.test.ts` (10) pins the guarded reads, the three
insert-site tags, and the lifecycle-only trigger list. Full suite 1416 green.
